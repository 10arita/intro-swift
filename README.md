# IntoL — iPhone 向けイントロクイズ

SwiftUI 製 iOS 17+ アプリと、Coolify 用 Node.js サーバーです。`rule.md` をゲーム仕様の参考にし、個人学習と少人数のプライベート対戦向けに作成しました。画面は白と赤を基調に、プレイでは人数、イントロ・サビトロ、音源を順に選びます。下部の「プレイ」を押すと最初のロゴ画面に戻ります。

## できること

| モード | 音源 | 条件 |
| --- | --- | --- |
| ひとりで | 同梱のオリジナル音源、サーバーの共有音源、Apple Music のプレイリスト | Apple Music の曲の再生には本人のサブスクリプションが必要 |
| みんなで | ホストの Apple Music のプレイリスト | 最大4人、全員が Apple Music の再生条件を満たす必要があります |
| サビトロ | iTunes Search API の試聴曲を検索、または Apple Music のプレイリストと照合 | ひとりでも最大4人でも遊べます。プレイリストの選択には Apple Music のライブラリアクセスが必要 |
| 共有音源対戦 | サーバー登録済み WAV | 最大4人 |

1曲30秒の PUSH、1文字5秒の4択、解答権、誤答・ライフ・得点、全員スキップ、最終順位、ソロの0〜100点と15段階ランクを実装しています。回答中は正解の文字数を表示しません。対戦サーバーが PUSH の到着順を判定します。ほぼ同時の PUSH で解答権を取れなかった場合もルームに残り、画面内に結果を通知します。プレイヤー欄は4人分を横一列に表示し、現在の問題の正解を「○」、誤答を「×」、未回答を「−」で表示します。PUSH時刻は解答権の判定前に記録します。プレイヤー欄は各問題の開始時に得点の高い順に左から表示し、PUSHがあればPUSHした順に左から並び替えます。まだPUSHしていないプレイヤーは得点順に続き、PUSH順位は各プレイヤーの欄に表示します。出題タイマーは0.01秒単位、PUSH時刻と平均PUSH時間は0.001秒単位で表示します。誤答者はSKIP投票の成立条件から除外します。通常モードの解答権人数は1〜4人（初期値2人）で、空き枠があれば複数人が並行して解答できます。PUSHした本人の曲はすぐに止まり、正解者が出ても受付中はほかの人がPUSHできます。30秒経過、全枠使用、または回答可能な人がいなくなると受付を終了し、全員の出題曲を止めます。受付終了後も進行中の解答は各文字の5秒制限で続行し、すべて終わってから正解曲を再生します。複数正解時は正解者のPUSH受付順に順位を付けます。1st正解ボーナスは正解者の中で最初にPUSHしたプレイヤーに適用します。1st誤答ペナルティは従来どおり、その曲で最初にPUSHしたプレイヤーが誤答した場合にだけ適用します。エンドレスモードでは解答権人数に関係なく1人ずつ解答し、回答中は全員の曲と出題タイマーが止まります。僅差でPUSHした人は解答待ちになり、前の人が誤答または時間切れになるとPUSH順に解答できます。待機者がいなくなった誤答後は停止位置から曲を再開します。各ラウンドでは「第○曲目」と読み込み表示を挟み、対戦は全員の準備完了後に5秒のカウントダウンを始めます。端末は通信の往復時間からサーバー時計との差を推定して同じ開始時刻に合わせ、端末内に保存した音源は再生時刻を予約します。Apple Music は MusicKit が時刻指定再生を提供しないため、通信・バッファリング・音声出力の遅延まで完全に一致させることはできません。

復習リストは「覚えてない」「覚えた」を各50曲、ソロ履歴は直近5回です。統計、ジャンル別正答率、8種類の称号、切断後5分以内の復帰、ホスト自動・手動交代にも対応しています。名前・アイコン・復習・履歴・統計・称号・音量設定はCloudKitのPrivate Databaseに保存し、端末にもキャッシュします。同じiCloudアカウントの別端末へプロフィールを復元できます。CloudKit未設定・未サインイン・オフライン時も端末で利用できます。ルームとフレンド申請・招待は引き続きサーバーの `DATA_DIR` に保存します。既存の端末とサーバーの個人記録はCloudKitへ取り込みます。

## CloudKitの設定

Apple Developer側の設定は別途必要です。[CloudKitの設定と動作確認](docs/cloudkit-setup.md)に、コンテナ作成、XcodeのiCloud設定、`.env` の `APP_CLOUDKIT_ENABLED=true`、初回同期、Productionへのスキーマ公開の手順をまとめています。現在のコンテナIDの既定値は `iCloud.com.intro.IntoL` です。CloudKit対応後も、対戦中の通信には既存のWebSocketを使います。

曲名の長音符「ー」と英字同士を直接つなぐハイフンは回答対象です。その他の記号は解答不要で、英字同士をつながない `-`、`(`、`feat` 以降も省略できます。対戦の最終順位は得点、同点なら残ライフで決め、失格者は最下位にします。リザルトの1〜3位は淡い金・銀・銅で表示します。ホストはルール未設定のルームを作り、待機画面でプレイリストとルールを選んで「ゲームを開始」を押します。その後、全員が音源を準備し、準備完了で自動的にカウントダウンへ進みます。終了後の「ルームに戻る」は同じ参加者と未出題曲の履歴を保ったまま、ルール未設定の待機画面に戻ります。次の対戦ではルールを変更しても未出題曲を優先します。同じルームのプレイヤーにフレンド申請を送り、承認するとフレンドになります。待機中のルームからフレンドを招待でき、受け取った人は「フレンド」タブから6文字のコードを入力せずに参加できます。

ルーム作成後、待機中のホストは「ハンデを設定」から参加プレイヤーごとに0〜30秒を指定できます。対象プレイヤーは各問題の再生開始から指定時間が過ぎるまでPUSHできず、残り時間が画面に表示されます。設定は開始後に変更できません。

### 対戦の通信方式

対戦中は認証付きの WebSocket 1本で PUSH・回答・準備完了などの操作と状態通知を送受信します。サーバーは到着順と制限時間を判定し、操作結果を同じ接続で返します。PUSH 直後は端末に判定中の状態を即座に表示し、相手の PUSH はサーバーからの通知で更新します。WebSocket に接続できない環境では従来の SSE 通知と HTTP 操作に切り替え、接続を約1分ごとに再試行します。SSE にも対応しない旧サーバーでは2秒間隔で状態を取得します。各端末に送る状態はその参加者の解答選択肢だけを含み、発表前の曲名は含みません。カウントダウン開始・30秒の受付終了・各文字の5秒制限もサーバー側のタイマーで通知します。

従来の0.5秒間隔の取得では、4人対戦が500ルーム同時に進むと最大約4,000件/秒の状態取得が発生し、相手の操作反映には最大約0.5秒かかります。WebSocket と SSE は合わせて最大2,000本の接続を維持し、15秒ごとに生存確認を行います。少人数対戦・単一サーバーの構成には妥当ですが、2,000人同時接続時のファイル記述子数、メモリ量、プロキシの WebSocket Upgrade 対応は実環境で確認してください。複数レプリカへ増やす場合は、ルーム状態と通知の共有基盤が必要です。ネットワークの往復時間や外部音楽サービスの再生開始時間は WebSocket だけでは短縮できません。

曲名に「~」「〜」「～」がある場合は、最初の記号とそれ以降を解答対象から外します。正解発表には元の曲名を表示します。

１文字目のダミーは音源元にかかわらず iTunes Search API で同一アーティストを検索し、上位６曲から正解曲を除いて異なる先頭文字をランダムに最大３つ選びます。足りない場合は同じ文字種の候補で補います。２文字目以降はプレイリストと同梱の曲名データから、同じ接頭辞を持つ別曲の次の文字、直前の文字に続く頻度が高い文字、正解と同じ文字種の候補の順に選びます。2015〜2026年の Billboard JAPAN チャートを基に約1,100曲の題名を追加し、ソロと対戦の両方で使います。小書き仮名と長音符はダミーに使いません。Songle でサビが見つかれば1.5秒手前から、見つからなければ曲長の32%を30〜90秒に収めた位置から Apple Music で再生します。サビトロは試聴音源の冒頭から再生します。曲名コーパスは選択肢用であり、追加した曲の音源を同梱するものではありません。

各問題の開始前には、端末でその曲の音源を準備します。共有 WAV と試聴音源は端末の一時領域へ読み込みます。Apple Music 音源は MusicKit が再生します。Apple Music には全出題曲の音声をアプリ側へ事前取得する API がないため、曲情報と再生可能性を確認しながら進行します。

プレイリストからの出題曲の照合は最大6曲を並行して行い、必要な数の未出題曲がそろった時点で終了します。照合済みの曲はアプリ起動中に再利用し、開始操作の通信に失敗した場合も準備済みの出題曲を保持して再試行します。すでに出題曲が確定した待機ルームでは、プレイリストを照合し直さずに開始します。並行処理・途中終了・キャッシュ・再試行の回帰テストは `sh scripts/test_playlist_preparation.sh` で実行できます。

## 先に Coolify サーバーを用意する

複数端末の対戦と iTunes 試聴曲を使うサビトロにはサーバーが必要です。Apple Music のソロプレイとデモには不要です。対戦を使う場合は、この変更を含むサーバーを再デプロイしてください。

1. このリポジトリを Coolify が参照できる Git リポジトリにプッシュします。
2. Coolify の **New Resource → Dockerfile** でビルド基準ディレクトリを `server`、Dockerfile をその中の `Dockerfile` にします。公開ポートは `3000`、レプリカは **1** にします。
3. HTTPS ドメインを設定し、環境変数 `PUBLIC_BASE_URL=https://あなたのドメイン` と `DATA_DIR=/app/data` を設定します。`PUBLIC_BASE_URL` の末尾に `/` を付けません。
4. **永続ボリュームをコンテナ内 `/app/data` にマウント**します。マウント先を変えた場合は `DATA_DIR` も合わせます。永続ボリュームがないと再デプロイ時に履歴と進行中ルームを失います。
5. デプロイ後、`https://あなたのドメイン/health` が `{"ok":true}` を返すことを確認します。アプリをビルドする Mac のルート `.env` に同じ HTTPS URL を `APP_SERVER_URL` として指定します。

サーバーの設定例は `server/.env.example`、アプリの設定例はルートの `.env.example` を参照してください。アプリのビルドでは `.env` から `APP_SERVER_URL` を取り込みます。

## Apple Music の設定

MusicKit for Swift を使います。Apple Music API の秘密鍵や手動の Developer Token はアプリに不要です。MusicKit が App ID を使って Developer Token を自動生成します。[Apple の設定手順](https://developer.apple.com/documentation/musickit/using-automatic-token-generation-for-apple-music-api)を参照してください。

1. [Apple Developer の Certificates, Identifiers & Profiles](https://developer.apple.com/account/resources/identifiers/list) で、このアプリ用の **Explicit App ID** を作成するか既存の App ID を開き、**App Services → MusicKit** を有効にします。
2. Xcode の **Targets → IntoL → Signing & Capabilities** で自分の Team を選び、Bundle Identifier をその App ID と完全に一致させます。現在のリポジトリの値は `com.intro.IntoL` です。署名プロファイルを更新して実機にインストールします。
3. Apple Music を利用できる Apple Account で iPhone にサインインし、Apple Music の有効なサブスクリプションを用意します。IntoL の「アカウント」で「Apple Music に接続」を押してライブラリへのアクセスを許可します。許可を拒否した場合は iPhone の設定から IntoL のメディアライブラリアクセスを変更します。
4. 「プレイ」→「ひとりで」→「イントロ」→「Apple Music」からプレイリストを選びます。対戦する場合は全員が Apple Music に接続し、ホストは「みんなで」→「イントロ」→「Apple Musicで作る」を選び、ルームの待機画面でプレイリストを選びます。対戦ではライブラリ曲を Apple Music カタログに対応付け、曲名のバージョン表記・アーティスト・曲長が一致しない候補は除外します。参加者の地域で再生できない曲があると、そのラウンドの準備が完了しません。

Apple Music のプレイリストはイントロクイズで利用できます。サビトロでは iTunes 試聴音源の検索か、Apple Music プレイリスト内の曲と試聴音源の照合を使います。Apple Music の正解発表では Songle にサビ情報がある場合はサビの1.5秒手前から、見つからない場合は曲の長さから推定した位置から再生します。ソロプレイでは対戦サーバーの設定がなくても端末から Songle に照会します。

## Xcode で起動・確認する

1. `cp .env.example .env` を実行し、対戦またはサビトロを使う場合は `APP_SERVER_URL` を記入します。値が空欄でもデモは動きます。`.env` は Git の管理対象外です。値を変えたらアプリを再ビルドしてください。
2. [IntoL.xcodeproj](IntoL.xcodeproj) を Xcode で開きます。
3. **Targets → IntoL → Signing & Capabilities** で自分の Team を選び、Bundle Identifierがご自身のApp IDと一致することを確認します。追加済みのiCloud capabilityに合わせて[CloudKitの設定](docs/cloudkit-setup.md)を行ってください。
4. iPhone 実機を選んで **Run**（⌘R）します。必要に応じて iPhone のデベロッパモードを有効化し、Mac を信頼します。シミュレータでもデモの画面と一部音源は確認できますが、Apple Music の実再生は実機で確認してください。
5. まず設定なしで「プレイ」→「ひとりで」→「イントロ」→「オリジナル音源」→「プレイ開始」→ PUSH → 4択 → 結果 → 復習を確認します。
   「ショートカット」アプリから「ひとりで練習」を実行すると、同じオリジナル音源のソロ練習を直接始められます。
6. サーバーを設定したら2台の iPhone で共有音源ルーム、Apple Music ルーム、サビトロを順に確認します。サビトロでは iTunes に一致しない曲を除外します。終了後は「アカウント」で記録の同期状態を確認します。
7. Wi-Fi を一時的に切って5分以内に戻し、同じルーム・得点・ライフに復帰することを確認します。ホストの退出と待機室の「ホストを譲る」も試せます。

署名なしの iPhone 向けビルド:

```sh
xcodebuild -project IntoL.xcodeproj -scheme IntoL -configuration Debug \
  -destination 'generic/platform=iOS' -derivedDataPath /tmp/IntoLDerived \
  CODE_SIGNING_ALLOWED=NO build
```

サーバーのテスト:

```sh
cd server
npm ci
npm test
npm run test:socket
```

CloudKit同期データの統合テスト（Mac上で実行。iCloudの設定は不要）:

```sh
sh scripts/test_cloud_profile.sh
```

ローカル起動は Node.js 22 以降で `cd server && node index.mjs` です。iPhone からアクセスする場合は HTTPS の Coolify 環境を使います。

この開発環境では iPhone 向けビルドとサーバーテストが成功しています。XcodeBuildMCP では iPhone 16 Pro (iOS 18.6) シミュレータでのビルド・起動と、デモの PUSH から正解発表まで確認できました。App Intent のビルドとショートカットのメタデータ生成も確認済みです。ただし、このシミュレータの「ショートカット」アプリでは追加したアクションを検索できず、ショートカットからの実行は未確認です。コマンドラインの `simctl` は CoreSimulator と Xcode のバージョン差により利用できません。

Apple Music の実再生、iTunes と Songle のライブ動作、複数 iPhone の同時再生は実機での確認が必要です。

追加した曲名は [Billboard JAPAN の年間 Hot 100](https://www.billboard-japan.com/charts/detail?a=hot100_year&year=2025) と [週次 Hot 100](https://www.billboard-japan.com/charts/detail?a=hot100) を基に [scripts/build_jpop_corpus.py](scripts/build_jpop_corpus.py) で生成しました。題名だけを収録し、順位・アーティスト情報・音源は含めません。

## 自作音源と Songle URL

自作または利用権のある WAV を `server/public/audio/` に置き、[server/catalog.json](server/catalog.json) に `id`、`title`、`artist`、`audioFile`、`durationMS`、`genre` を追加して再デプロイします。任意で `artworkURL`、`trackURL`、Songle に登録済みの元動画 `songleURL` を設定できます。ファイル名は英数字・`_`・`-` と `.wav` を使用してください。サーバーは登録済み WAV だけを配信します。初期6曲と PUSH 音は [scripts/generate_demo_audio.py](scripts/generate_demo_audio.py) で再生成できます。

## 利用条件について

個人学習用でも外部サービスの利用条件は適用されます。Apple の [iTunes Search API 文書](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/index.html) には試聴音源の用途制限が記されています。外部サービスの接続可否と利用条件を確認した上で使用してください。デモと自作音源の経路は外部連携なしで使えます。
