# サビ位置の匿名報告（Discord）

ソロ・対戦の正解発表に「サビ位置の相違を報告する」を表示します。正解曲の再生が始まるとボタンを押せます。確認画面はスケールインで現れ、匿名送信であることを説明します。「視差効果を減らす」が有効な場合はフェードで表示します。

## 通知先の設定

1. Discord に開発者だけが閲覧できる報告用の**テキストチャンネル**を作成します。
2. そのチャンネルの「チャンネルを編集 → 連携サービス → ウェブフック」で Webhook を作成し、URL をコピーします。
3. Coolify のサーバー環境変数に `DISCORD_CHORUS_WEBHOOK_URL` として URL を設定し、この版のサーバーを再デプロイします。Webhook URL は秘密情報なので、アプリの `.env` や Git に含めないでください。
4. アプリの `APP_SERVER_URL` はこのサーバーの HTTPS URL にします。Apple Music のソロでも報告を送るにはサーバー設定が必要です。
5. 実機で正解発表後に報告し、指定したチャンネルに届くことを確認します。

通常のテキストチャンネルを使ってください。フォーラムを使う場合は Webhook URL に既存スレッドの `thread_id` が必要です。Webhook の `wait=true` で Discord が返すメッセージIDを確認してから送信成功にします。[Discord の公式仕様](https://docs.discord.com/developers/resources/webhook#execute-webhook)に基づき、メンションを無効にしています。

## 届く情報

- 曲名、アーティスト、曲ID、曲の長さ、ジャンル、曲へのリンク
- 実際に再生できた処理：サビDB（手動確認済み） / サビDB（Songle取得済み） / Songle / プレビュー音源の冒頭 / 曲長からの推定 / 曲データのサビ位置
- 再生した音源：Apple Music フル音源 / 共有・デモのフル音源 / iTunes プレビュー
- 再生開始位置（秒、ミリ秒精度）、ソロ・対戦の区別、アプリのバージョン・ビルド番号
- 報告ごとに発行するランダムな報告ID、サーバーの受信日時

DBの再生に失敗してプレビューに切り替わった場合は、**プレビュー**として報告します。曲長から推定した場合は、準備した音源の長さから求めた実際の開始位置を送ります。旧サーバー由来の取得元が不明なサビ位置は「曲データのサビ位置（旧データでは取得元不明）」として区別します。新サーバーは DB / Songle の取得元を正解発表の曲データにも付けます。

Songleから取得してSQLiteに保存したサビ位置を使った場合は、`songle_database`として「サビDB（Songle取得済み）」を通知します。その場のSongle照会（外部APIの応答キャッシュを含む）は`songle`として「Songle」を通知します。`databaseConfigured`はDBの有無を示すだけで、DBに曲が見つからずSongleへ進んだ場合も`true`になるため、DBを使ったかどうかは実際に成功した取得元で判定します。この区別を反映するには、サーバーとアプリの両方を更新してください。

DBの照合は曲名とアーティストで行い、アルバム名や曲IDの違いでは除外しません。Songle動画の曲長と配信版の曲長が異なる場合も、保存したサビ開始位置が再生対象の曲長内であればDB情報を利用します。

名前、アカウント・プロフィール・端末ID、ルームコード、プレイリスト、成績、認証トークンは報告に含めません。サーバーも許可した項目だけを転送・保存し、曲リンクの追跡パラメーターを除きます。報告には認証情報を付けません。通信先のサーバーやプロキシでは通常の通信として接続元IPを扱うため、アクセスログの扱いは運用側で確認してください。

## 失敗・重複への対応

通信中はスピナーと「報告を送信しています…」を表示します。成功すると、緑の円を上から時計回りに約0.55秒で描き、その直後に内側のチェックマークを左から右へ約0.22秒で描きます。「ご報告ありがとうございます」を表示し、描画完了後に約1.5秒待って報告画面を自動で閉じます。報告ボタンは「報告済み」に切り替わります。「視差効果を減らす」が有効な場合は、完成した円とチェックをそのまま表示し、約1.5秒後に閉じます。

Discord の未設定、接続失敗、レート制限などは確認画面でエラーとして表示し、同じ報告IDで再試行できます。サーバーは成功済みの報告IDを保持し、同時送信や成功応答の消失による再送をまとめます。匿名報告の転送はサーバー全体で最大30件/分です。

`DATA_DIR` に永続ボリュームがある場合は、匿名の報告内容と成功記録を `chorus-reports.json` に保存します。重複防止の対象は直近30日・最大5,000件で、新しい報告の保存時に古い記録を除きます。永続ボリュームがない場合、再起動後の重複防止は維持できません。Discord へ届いた直後にサーバーが停止した場合や Discord の応答が失われた場合には、再送で重複する可能性があります。報告IDで同じ報告かを確認できます。

## 検証

- `sh scripts/test_chorus_report.sh`：匿名ペイロード、送信確認、再試行ID、失敗
- `sh scripts/test_reveal_audio.sh`：再生優先順位、切替後の取得元、再生失敗・キャンセル
- `cd server && npm test`：Discord送信（モック）、匿名化、入力検証、失敗、重複、再起動、HTTP受付
- Debug の `--ui-preview=reveal`、`--ui-preview=solo-reveal`、`--ui-preview=reveal-large-text`：確認画面と通信失敗の画面検証。これらは実際の Discord に送信しません。
- Debug の `--ui-preview=reveal-report-success`、`--ui-preview=solo-reveal-report-success-dark`、`--ui-preview=reveal-report-success-large-text`：実通信を使わず、約2秒の送信中表示から完了演出まで確認できます。
