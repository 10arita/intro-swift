# IntoL 正式公開の実施計画

更新日：2026年10月17日（日本時間）

## 公開する価値と今回の前提

音楽との出会い、曲を覚えること、復習して音楽に親しむことを目的とする。現在のイントロ出題、早押し、得点、ランク、対戦の実際の挙動も、問い合わせ・申請資料にそのまま記載する。目的に合わせて説明文だけを変え、実装を隠すことはしない。

収益源の希望は広告と広告削除のアプリ内課金。広告事業者は未定。広告削除は買い切りの非消耗型を候補とし、金額・商品IDは未確定。広告SDKの導入、課金商品の登録、配信開始、問い合わせの送信はまだ行っていない。

サポートページはGoogle Sites、返信を希望する問い合わせの受付はGoogleフォームを利用する方針。公開運営者名はKaito Arita、問い合わせの保存期間は対応完了後90日間としてユーザー確認済み。Google側にサイト2ページとフォームを作成し、ユーザー指定URLへの導線とサポート・フォームの公開用文面を非公開で保存済み。更新後の`.env`をアプリに反映し、フォームへの直接リンクも追加した。アプリ内の匿名のご意見・サビ位置の報告（Discord宛て）は別機能として維持する。ポリシーの未確定事項、返信・削除運用、一般公開後の実地確認とApp Store Connectへの設定は未完了。公開操作はユーザー本人が行う。[作成済みの編集先・手順](google-sites-forms-setup.md)を参照。

紹介目的の試聴素材の利用条件と、MusicKit経由でのApple Musicアクセスの収益化条件は別々に確認する。紹介・学習目的という説明や、広告を結果画面に置くことだけで適合すると判断しない。

## 今回の実装

- `PrivacyInfo.xcprivacy` をアプリのResourcesへ追加。UserDefaultsはCA92.1、経過時間計測は35F9.1、アプリ内のファイル時刻はC617.1を宣言。広告SDK追加時には再評価する。App Privacyの収集項目の申告は別途必要。
- アカウント画面に「このアプリについて・サポート」と「アカウントとデータの削除」を追加。データの保存先・他プレイヤーへの表示・Apple Musicの別契約・Discordへの送信を説明。
- 公開ポリシー・利用規約・サポートのHTTPS URLと運営者・メールを、公開用設定として追加。未設定の外部リンクは表示しない。これだけで公開ポリシーの準備完了にはならない。
- 認証付き `DELETE /profile`、フレンド・申請・招待・ルーム参加情報の削除、古いIDの再登録防止、再試行を実装。
- iCloudの記録を削除マーカーで置換し、古い端末のデータとのマージを遮断。以降はCloudKitの`schemaVersion=2`を使用し、削除対応前のアプリによる上書きを防ぐ。新しいRecord Typeやフィールドは追加しない。
- 削除処理の受付情報をKeychainへ保存し、途中で終了しても再試行できるようにする。完了するまで同期と新規プレイを止める。認証情報の分かる旧プロフィールも対象に含める。
- 復習画面でのApple Music試聴への代替を除去。Apple Musicの復習には認可・有効な契約が必要。同梱の自作デモは維持する。
- StoreKit 2で広告削除商品の取得、購入、承認待ち、復元、返金・取り消し後の権利更新を扱う基盤を追加。表示価格はApp Storeの商品情報を使用する。権利確認完了までは広告を表示しない判定を提供。
- 課金は既定で無効。広告SDKが未導入なので、課金を有効にして公開しない。広告が実際に除去されることを検証してから有効化する。

## 1. 音楽利用と収益化の仕様を確定する

担当：運営者、必要に応じてApple・権利者・専門家。実装だけでは完了しない項目。

### Appleへ提示する現行の再生フロー

1. 利用者がApple Musicへのアクセスを許可し、再生可能な契約を確認する。
2. 利用者がプレイリストを選び、開始を操作する。ランク測定では共通曲集を使う。
3. イントロを最大30秒出題。PUSH・時間制限・正誤・スキップ等に応じて再生を制御する。
4. 正解発表でサビDBまたは曲長から決めた位置へ移動して再生する。
5. 復習へ保存できる。復習はMusicKitのフル音源を再生し、位置を操作できる。
6. 対戦は最大4人。各端末が本人のApple Music契約で再生し、サーバーはタイミングと操作を扱う。Apple Musicの音声をサーバーで配信しない。

### 広告・課金の候補仕様（確認前の案）

| 項目 | 案 |
| --- | --- |
| バナー | プレイ終了後の結果画面のみを初期候補とする。配置・音楽との関係をAppleに確認する |
| 全画面広告 | 初版では導入しない案。対戦の待機・開始・問題間には挿入しない |
| リワード広告 | 再生、出題回数、Apple Music機能を解放する用途には使用しない |
| 広告削除 | 買い切り。Apple Musicの再生能力、曲数、音源品質、対戦の有利不利を変えない |
| データ | プレイリスト、好きな曲、音楽の利用履歴を広告SDKへ渡さない |
| 追跡 | 追跡を行わない構成を第一候補とする。SDKの実際の収集・送信・広告計測を確認して決定する |
| 障害時 | 広告の取得に失敗してもプレイを妨げない。購入済み権利を確認する前に広告を表示しない |

Appleの回答と必要な許諾確認に基づき、広告対象を変える、音楽から独立したサービスを検討する、または広告付き利用を許諾された別の音源方式へ変更する。どの代替案も自動的に許容されるとは扱わない。事前問い合わせは審査承認の保証ではない。

### 紹介・復習の体験を強める今後の候補

- 曲名・アーティストと独自の紹介文を正解後に表示する。紹介文の出典・執筆権利も管理する。
- Apple Musicで曲を開く導線をソロ・対戦・復習で揃える。公式バッジの使用条件を確認する。
- 再生・一時停止・スキップ・全曲を聴く導線と、出題時の制御の整合性を確認する。
- ストアのカテゴリ、説明、スクリーンショットを実際の完成機能に合わせる。

## 2. 音源・データ・素材の台帳

許諾書がリポジトリにないことだけで、許諾未取得とは断定しない。取得済みのものは取得先・日付・対象・条件と証跡を追記する。

| 対象 | 現状・必要な判断 |
| --- | --- |
| MusicKitの再生・制御 | 30秒出題、自動停止、サビ移動、対戦との組み合わせを提示して確認する |
| Songle由来のサビ位置 | 商用利用、DBへの保存・移行、アプリへの提供方法の承諾を確認。ライブAPIを呼ばなくても対象 |
| 歌ネット由来の曲集・難易度 | 順位を用いた選定と難易度設定の再利用条件を確認。代替する場合は独自に選定・評価する |
| Billboard由来の題名コーパス | 取得方法と商用利用条件を確認。個々の題名という事実とデータの取得・再利用条件は区別する |
| OtoLogic効果音 | 今回クレジットとCC BY 4.0へのリンクを追加。使用ファイルの原本・変更内容を台帳に記録する |
| OpenTracksのBGM・正解音 | 「曇った宝石／かずち」「正解・ピンポン音／Causality Sound（Track 1）」と公式ファイルの完全一致を確認。商用利用無料・クレジット任意。同梱方法と容易な音源複製を禁じる条件への適合は未確認。[音源台帳](audio-licenses.md)参照 |
| 効果音ラボの不正解音 | 「クイズ不正解2」と公式ファイルの完全一致を確認。商用利用無料・クレジット任意。操作音の同梱は規約で認められる。[音源台帳](audio-licenses.md)参照 |
| ジャケット・紹介動画 | アプリ内表示・機能を示す画像と、宣伝への転用の権利を確認する |

## 3. 運営者の入力が必要な設定

`.env.example` の公開用設定を `.env` に追加する。秘密情報をiOS用設定へ追加しない。

| キー | 内容 |
| --- | --- |
| `APP_OPERATOR_NAME` | アプリ内に公開する運営者名。Appleへの審査担当者名とは別。必要な正式名称の表示は登録形態・法令に合わせる |
| `APP_SUPPORT_EMAIL` | 任意の公開メール。Googleフォーム方式では空欄でよい。返信用メールは運営側で別途用意する |
| `APP_PRIVACY_POLICY_URL` | Google Sitesで公開したプライバシーポリシーページのHTTPS URL |
| `APP_TERMS_URL` | 独自規約を公開する場合のHTTPS URL。Apple標準EULAとは別で、一律の必須項目ではない |
| `APP_SUPPORT_URL` | Googleフォームへの案内・FAQを含むGoogle Sitesの公開HTTPS URL。編集用URLやフォーム単体のURLではない |
| `APP_SUPPORT_FORM_URL` | 任意。Googleフォームの回答者用HTTPS URL。指定するとアプリにもフォームの直接リンクを表示 |
| `APP_MONETIZATION_ENABLED` | 現時点では`false`を維持 |
| `APP_AD_REMOVAL_PRODUCT_ID` | App Store Connectで登録する実際の非消耗型商品ID |

ポリシーの最終化では、運営者、保存先、取得目的、保持期間、削除、委託先・国外取扱い、問い合わせ方法、改定日を実態に合わせる。本番アクセスログ・バックアップ・Discordの保持期間は未確定であり、日数を推測して記載しない。課金販売では取引条件・必要な事業者表示も確認する。

[プライバシーポリシー案](privacy-policy-draft.md)、[サポートページ案](support-draft.md)、[Googleフォームの設問案](google-support-form-draft.md)を用意した。未確定の`{{...}}`を解決してから公開する。フォームの回答者にはログインを要求せず、回答内容は公開しない。Googleフォームと返信メールの保存期間・削除運用も確定する。

## 4. 削除機能の運用条件

- アプリに先行して、削除APIに対応するサーバーをデプロイする。旧サーバーの404応答を削除成功と扱わない。
- CloudKitの既存`IntoLUserProfile`の`payload`と`schemaVersion`をProductionへ公開しておく。削除後のレコードは個人の記録を含まないマーカーとして残る。
- 削除済みのIDと認証トークンは、再登録防止と再試行認証のためSHA-256ハッシュをサーバーへ残す。生のID・トークンや名前・写真・成績は削除済みプロフィールとして保存しない。
- 削除は既知の認証情報で削除できるプロフィールを対象とする。古い環境にデータがあり認証情報が失われている場合の本人確認・サポート手順は別途必要。
- `state.json`の稼働中の情報は更新するが、外部バックアップの消去・世代管理は自動化していない。保持期限を定め、復元時には削除済み状態を再適用する手順を用意する。
- 本番はCoolifyを利用する国内サーバーで、ユーザー関連データを含むバックアップを作成し、そのバックアップは削除されないとのユーザー回答済み。「バックアップなし」「削除後に全保存先から消去済み」とは案内しない。複製を消去する方法・保持期限・復元時の対応を決定し、Appleのアカウント削除要件との整合性を解決する必要がある。文面への注意書きだけで完了とは扱わない。
- 匿名報告はプロフィールIDと関連付けていないため、アカウント削除ではDiscordから削除できない。本文に個人情報が含まれた場合の受付・削除窓口を用意する。
- 新しいアプリが同期することで古い端末の記録を置換する。オフライン端末や、削除に未対応の旧アプリ内の端末データを遠隔で消去する機能ではない。

### 実機試験

1. 新規利用、認可拒否、Apple Music未加入・契約失効、配信終了曲、異なる地域。
2. ソロ・復習・2〜4台対戦、途中参加、通信断・復帰、Bluetooth、バックグラウンド。
3. 名前・写真・履歴・成績・フレンドを用意した状態で削除し、端末・サーバー・CloudKitを確認する。
4. サーバー削除の応答消失、サーバー削除後のCloudKit通信失敗、アプリ終了・再起動、再試行。
5. 削除中のiCloudアカウント変更。誤ったアカウントを削除せず、元のアカウントで再試行できること。
6. 別端末をオフラインにして記録を追加し、削除後に同期。古い記録と認証情報が復活しないこと。
7. 購入成功、キャンセル、承認待ち、再インストール、別端末で復元、返金・取り消し。課金はSandboxで試験する。
8. 広告取得失敗、追跡拒否、購入権利の確認中・購入直後・復元後に広告を表示しないこと。
9. 小さい画面、最大文字サイズ、VoiceOver、ダークモード、視差効果を減らす設定。

設定画面の確認用に、Debugの`--ui-preview=app-information`と`--ui-preview=account-deletion`を追加した。`-dark`、`-large-text`を付けると各表示を確認できる。破壊的な操作の試験は、実際のアカウントではなく隔離したテストデータで行う。
