# サーバー保存データの確認

確認日：2026年10月17日。対象はこのリポジトリの現行コード。本番サーバー、実ユーザーの保存ファイル、バックアップ、秘密値は閲覧していない。

## 結論

「個人に関するデータは端末またはCloudKitにしか保存しない」という構成ではない。詳細な個人記録は現在のアプリでは端末・CloudKitを中心に管理するが、対戦サーバーにもユーザーと結び付く情報を保存する。

通常のDocker構成では`DATA_DIR=/app/data`であり、その配下の`state.json`にプロフィールとルームを保存する。このファイルや永続ボリュームをバックアップ対象に含める場合、バックアップにも以下の情報が含まれる。

## 保存先の対応

| データ | 現行アプリ・サーバーの動作 | 主な根拠 |
| --- | --- | --- |
| 名前、アイコン画像、プロフィールID | アプリがサーバーへ送信し、プロフィールとルームへ保存する | `IntoL/RoomService.swift:882`、`server/index.mjs:577`、`server/index.mjs:676` |
| 成績の概要、称号、最高ランク | プレイ回数、回答回数、正解数、平均PUSH時間、称号、最高ランクを送信・保存する | `IntoL/RoomService.swift:897`、`server/index.mjs:568` |
| プロフィール認証情報 | 登録時にサーバーへ渡す。サーバーは`secret`として保持し、`state.json`へ保存する | `IntoL/RoomService.swift:854`、`server/index.mjs:559`、`server/index.mjs:52` |
| フレンド関係、申請、招待 | 関係先のID、名前、ルームID、日時等をプロフィールへ保存する | `server/index.mjs:215`、`server/index.mjs:727`、`server/index.mjs:739` |
| ルーム・対戦情報 | 参加者のID、名前、画像、セッション認証情報、得点、回答・操作、選曲情報等をルームへ保存する | `server/index.mjs:675`、`server/index.mjs:52` |
| 現行版の詳細な復習・履歴・統計・音量 | 端末とCloudKit Private Databaseで管理。現在の`publishProfile`はこれらの詳細を送信せず、成績概要だけを送る | `IntoL/CloudProfile.swift:24`、`IntoL/CloudProfileService.swift:49`、`IntoL/RoomService.swift:896` |
| 旧版の復習・履歴・統計 | サーバーは引き続き受け付け、既存データを保持する。CloudKitへの取り込みはサーバーからの消去ではない | `server/index.mjs:590`、`IntoL/AppModel.swift:917`、`docs/cloudkit-setup.md:56` |
| 匿名のご意見・サビ位置の報告 | Discordへの転送に加え、本文や曲情報を含む受付記録をサーバーのJSONファイルへ保存する | `server/anonymous-reports.mjs:55`、`server/feedback.mjs:39`、`server/chorus-reports.mjs:73` |

保存はメモリだけではない。HTTP処理後に保存を予約し、`saveStateNow`でファイルを書き換える。再起動時は同じファイルから復元する。`server/index.mjs:21`、`server/index.mjs:48`、`server/index.mjs:1138`を参照。

現在の認証情報は`state.json`にハッシュではなく文字列として保存される。削除済みプロフィールに対する再登録防止用のハッシュとは別物である。バックアップも機密性のあるデータとして取り扱う必要がある。

## テスト用データによる再現

一時ディレクトリにのみ保存する隔離実行で、次を確認した。実在する名前・画像・認証情報は使わず、外部への通信も行っていない。匿名報告のDiscord応答はモックに置き換えた。

- 現行クライアントと同じプロフィール概要の入力から、名前・アイコン・成績概要・最高ランク・認証情報が`state.json`へ保存される。
- フレンド関係・申請、ルームの参加者・認証情報・曲情報も保存される。
- 新規プロフィールへ概要だけを送った場合、詳細な履歴・復習は空、旧形式の詳細統計は`null`となる。
- 旧形式の履歴・復習・統計を保存してから現行形式の概要を送っても、旧データは消去されない。
- 匿名のご意見本文が`feedback-reports.json`に保存される。
- `state.json`のテスト用コピーをバックアップとして作成後、削除ハンドラーを直接実行すると稼働中ファイルからは対象プロフィールが除去されるが、独立したコピーには名前・認証情報が残る。

最後の項目は削除関数の直接実行による確認であり、アプリからHTTP経由の削除が成功することを示すものではない。既に確認したHTTP入口の`DELETE`拒否は未修正。

## 実バックアップのユーザー確認と残る対応

ユーザーから、前述のサーバーデータがバックアップされ、そのバックアップは削除されないとの回答を得た。これはユーザーからの確認であり、実際のバックアップを開いて独立に検証したものではない。正確な対象パス、保存方式、保存先、アクセス権限等は今回調査していない。

- `DATA_DIR/state.json`、報告のJSONファイル、またはそれらを含む永続ボリューム・サーバー全体のスナップショットが対象なら、ユーザー関連データもバックアップされる。
- 今回の回答を受け、「端末・CloudKitだけにユーザー情報がある」「バックアップにユーザー情報はない」という前提は使用しない。
- バックアップの保持期限、削除依頼時の処理、復元による削除済みデータの復活防止は未決定。削除されない複製の問題は注意書きだけでは解決しないため、公開前に運用と実装を見直す必要がある。今回、本番設定変更・実データ削除・公開操作は行っていない。
