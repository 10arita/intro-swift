事業者名・メールサービス名を一律に全列挙するというAppleの規定ではないが、国外での取扱いの要否等を判断するためには実際の環境の確認が必要。サーバーのURL・IPアドレス・管理用接続先を公開ポリシーへ追記する趣旨ではない。[Appleのプライバシー規定](https://developer.apple.com/app-store/review/guidelines/#privacy)、[外国クラウド利用時の情報提供（個人情報保護委員会）](https://www.ppc.go.jp/all_faq_index/faq1-q10-25/)を参照。

## 2. Googleフォームを作成する

1. 所有者のGoogleアカウントで[Googleフォーム](https://forms.google.com/)を開き、空白のフォームを作成する。
2. [設問案](google-support-form-draft.md)のタイトル、説明、設問、セクション分岐、確認メッセージを入力する。`{{...}}`は公開前に実値へ置き換える。
3. Google側のメールアドレス自動収集は使用しない。返信希望者にだけセクション分岐で返信先を入力してもらう。
4. 「回答を1回に制限する」をオフにし、組織内限定・確認済みメール等のログインを必要とする設定を使わない。ファイルアップロードの設問も追加しない。
5. **「結果の概要を表示する」はオフ**にする。問い合わせ本文・メールアドレスが他の回答者へ見える状態にしない。回答の編集も初期構成ではオフにする。
6. フォーム・回答の編集権限は所有者と必要な担当者だけに限定する。回答者向け一般アクセスと、編集者・回答データの共有を混同しない。
7. 公開準備ができたら、回答者アクセスを一般のユーザー向けに設定してフォームを公開する。**回答者用のURL**をコピーする。`/edit`で終わる編集URLや回答管理画面を公開しない。
8. 公開したポリシーURLをフォームの説明と確認欄へ反映するまで、実際の問い合わせ受付は開始しない。フォームとサイトを相互にリンクして公開する際は、未完成の状態で放置しない。

現在のGoogleフォームには公開操作がある。[Google公式の公開・共有手順](https://support.google.com/docs/answer/2839588?hl=ja)で、利用アカウントのUIを確認する。同資料は、回答の概要を有効にすると回答の全文が回答者へ共有されることも説明している。

## 3. Google Sitesを作成する

1. [Google Sites](https://sites.google.com/)で空白のサイトを作成し、サイト名を「IntoL サポート」にする。ここで案内する名称・URLは作成案であり、確保済みではない。
2. 次の2ページを作成する。独自利用規約を準備する場合のみ3ページ目を追加する。

| ページ | 原稿 | 推奨カスタムパス |
| --- | --- | --- |
| サポート | [サポート原稿](support-draft.md) | `support` |
| プライバシーポリシー | [ポリシー原稿](privacy-policy-draft.md) | `privacy` |
| 利用規約（必要な場合） | 最終化した独自規約 | `terms` |

3. Markdownの管理用注記・表の記法をそのまま貼り付けず、Google Sitesの見出し・本文・リンクとして整える。草案の注記や`{{...}}`が残っていないことを確認する。購入が無効な公開版では、原稿内の課金準備用の節を削除する。
4. サポートページの目立つ位置に「お問い合わせフォーム」ボタンを置き、Googleフォームの回答者用URLへリンクする。初期構成では埋め込みよりリンクボタンを使用し、iPhoneでもフォームへ移動できることを確認する。
5. ナビゲーションと各ページの末尾から、サポート・プライバシーポリシーへ移動できるようにする。独自利用規約がない場合は、空の規約ページ・壊れたリンクを置かない。
6. Google Sitesのプレビューでスマートフォン表示を確認する。Google Analytics等の解析設定は初期構成では追加しない。Google自身のサービスによる情報の取り扱いまで無くなるという意味ではない。
7. 公開用アドレスを決め、公開済みサイトの閲覧対象を一般公開にする。編集権限や回答データまで一般公開しない。
8. [Google公式の公開・共有手順](https://support.google.com/sites/answer/6372880?hl=ja)に従い、実際の公開ページからURLをコピーする。編集画面・プレビュー画面のURLをアプリへ設定しない。

## 4. 問い合わせ対応と削除の運用

- Googleフォームの回答を定期的に確認し、必要な担当者だけがアクセスする。返信用メールから手動で回答する。自動返信、受付番号の自動発行、自動削除は今回実装していない。
- 返信不要の送信は返信先を収集しない。アプリ内の匿名のご意見・サビ位置の報告は従来どおりDiscordへ届き、Googleフォームとデータ経路が異なる。
- Googleフォームの送信内容はプロフィールIDと自動連携しない。アプリのアカウント削除だけでフォームの回答やメールも削除されるとは案内しない。
- Discord上の匿名報告は受信日から90日後に手動削除する。フォーム・返信メールの対応完了後90日とは別に期限を管理する。自動削除は今回実装していない。
- 対応完了日と90日後の削除期限を、アクセス制限した運営用台帳へ記録する。期限経過後、フォームの回答と返信メールの両方を運営者が削除する。自動削除は未導入。スプレッドシート、CSV、バックアップ等へ複製した場合は、それらも削除対象・アクセス管理の台帳へ加える。フォームからの削除が他の保存先へ自動反映されるとは扱わない。
- 削除相談では必要最小限の情報で対象を特定する。Apple Accountのパスワード・認証コード・アプリの認証トークンを送ってもらう方法は使わない。
- Google側の保持・削除の扱い、運営者側の契約・国外での取り扱いを確認し、ポリシーとApp Privacyを実態に合わせる。

### 残る環境確認（公開必須項目を一律に増やす趣旨ではない）

- 対戦サーバーの国内設置はユーザー回答済み。提供環境の管理者が個人データへアクセスする範囲、必要に応じて提供条件を確認する。接続先URL・IP・認証情報を公開原稿へ記載するためではなく、必要な説明と削除対応の範囲を決めるための確認。
- アクセスログ・バックアップを運営者が管理しないことと、提供環境に記録・複製が存在しないことは異なる。外部管理者へ記録項目、保持、削除・復元時の対応を確認する。問い合わせ・Discordの90日間の方針を当てはめない。
- バックアップ自体が存在しない場合と、個人データを含むバックアップが期限なく残る場合を区別する。「定期削除しない」との説明だけで、どちらかを推測しない。後者の場合、公開文面への記載だけでアカウント削除の対応が完了するとは扱わない。[Appleのアカウント削除要件](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion)に照らし、保持理由・消去または置換の方法・復元時の対応を確認する。
- `server/anonymous-reports.mjs`は報告本文等を含む重複防止用の受付記録をファイルへ保存する。実装上の有効期限は30日だが、期限切れファイルの定期消去を行う実装ではないため、「サーバー上から30日で確実に消える」とは案内しない。外部管理者と消去方法を確認する。
- 削除マーカーは現在のコードでは期限付き消去を行わない。復活防止の必要性と、利用者の削除依頼に対する説明・保持方針を確定する。
- GoogleフォームとDiscordでの手動削除は、90日の期限が過ぎた記録を毎日確認する運用を用意する。今回、外部サービスの設定変更・実データの削除・自動化の作成は行っていない。

## 6. アプリとApp Store Connectへ反映する

ルートの`.env`に実際の公開URLを設定し、アプリを再ビルドする。**以下は書式例であり、そのまま公開版に使用しない。**

```dotenv
APP_OPERATOR_NAME="Kaito Arita"
APP_SUPPORT_URL=https://sites.google.com/view/your-published-site/support
APP_SUPPORT_FORM_URL=https://docs.google.com/forms/d/e/your-published-form/viewform
APP_PRIVACY_POLICY_URL=https://sites.google.com/view/your-published-site/privacy
APP_SUPPORT_EMAIL=
APP_TERMS_URL=
APP_MONETIZATION_ENABLED=false
APP_AD_REMOVAL_PRODUCT_ID=
```

Googleフォームの回答者用URLはサポートページ側のボタンと、アプリの`APP_SUPPORT_FORM_URL`に設定する。`APP_SUPPORT_URL`はFAQ等を含むサポートページのまま維持する。フォーム専用設定は任意で、未設定なら直接リンクを表示しない。いずれも公開用情報であり、Googleの秘密鍵は不要。公開予定URLを先に設定していても、公開先が正常に開けることを確認するまで配布しない。サーバー・CloudKitの既存設定を上書きしない。

App Store Connectの「サポートURL」には同じ公開サポートページ、「プライバシーポリシーURL」には公開ポリシーページを設定する。「App Reviewに関する情報」の審査担当者の連絡先は別であり、これらのページやアプリに転記しない。Appleへの事前問い合わせや収益化の確認も、このサポート窓口の準備とは別の作業。

法令上必要な事業者表示、個人登録時のApp Store販売元名、EUトレーダー情報などの公開要件がなくなるわけではない。
