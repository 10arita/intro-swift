# コードレビュー・バグ修正（2026-10-12）

SwiftUIアプリ、対戦サーバー、プロフィール同期、音源・画像キャッシュ、選曲・採点・復習、サビDBと収集・同期スクリプト、ビルド設定を確認しました。発見した以下の8件を修正しています。

| 優先度 | 問題と発生条件 | 修正 |
| --- | --- | --- |
| P1 | プロフィール登録の応答待ちでIDまたはサーバーが変わると、古いBearerトークンを現在のIDのKeychain項目へ保存してしまう | リクエスト開始時のID・接続先・保存キーを保持し、切り替え後の応答をキャンセル扱いにする。元の再登録用認証情報は保持 |
| P1 | 不正なリクエストURLで、HTTPハンドラーの例外が処理されずサーバー停止につながり得る | URLの解析を例外処理し、400を返す |
| P2 | ホストだけが切断後5分を超えても古いセッションを復活できる | ホストにも参加者と同じ期限を適用し、残った最古の参加者へ引き継ぐ |
| P2 | 退出・再参加で以前の音源準備完了が残り、準備前にゲームやカウントダウンへ進む | 退出・期限切れ時に準備完了、SKIP投票、ハンデを解除 |
| P2 | 自動ホスト交代では、旧ホストのライブラリ情報が待機室に残る | 手動・退出・期限切れの交代処理を共通化し、未準備のプレイリスト情報を消す |
| P2 | 認証付きGETでもゲーム開始・退出などの操作が実行できる | 状態取得はGET、操作はPOSTに限定し、それ以外は405を返す |
| P2 | HTTP 200で届いた破損音源をキャッシュすると、再試行しても同じファイルで失敗し続ける | 再生可否の検証に失敗した音源キャッシュを削除し、再ダウンロード可能にする |
| P2 | 復習音源の再生中にショートカット等からゲームを始めると、背後に残る復習画面の音源が重なる | セッションの表示開始で復習タスク・専用プレイヤーを停止。ゲームが使い始めた共有MusicKitプレイヤーは停止しない |

主な修正箇所は `IntoL/RoomService.swift`、`IntoL/GameAssets.swift`、`IntoL/ReviewView.swift`、`server/index.mjs` です。

## 確認の範囲

復習画面からゲームへの切替は状態管理のコード確認とビルドで検証しました。Apple Musicの契約・実機音声出力、実アカウントのCloudKit同期、ショートカット経由の画面操作は実機での追加確認が残ります。今回の修正はローカルに保存済みで、サーバーへの反映には再デプロイが必要です。
