# Apple Music サビ位置登録ツール（Debug限定）

Apple Musicのフル楽曲をMusicKitで再生し、聴いて確認したサビ開始時刻を提出する一時的な開発者ツールです。提出するたびに端末内のXLSXが自動更新されます。有料APIやSongleは使いません。

## 開き方

1. XcodeでIntoLを **Debug** ビルドし、Apple Musicを利用できる実機にインストールします。
2. アプリの「アカウント」→「接続・設定」→下部の「開発者ツール」→「Apple Musicのサビ位置を登録」を開きます。
3. 「Apple Musicに接続」を押し、アクセスを許可します。フル再生にはApple Musicのサブスクリプションが必要です。

XcodeのScheme → Run → Argumentsに `--chorus-tool` を追加すると、この画面を直接開けます。通常の起動に戻す際は引数を外します。Releaseビルドでは画面・再生処理・書き出し処理をコンパイルしません。

## 曲の選び方

- **プレイリスト**：「Apple Musicから選ぶ」でプレイリストを選び、曲を選択します。アーティスト順に表示します。
- **元のIntoL.txt**：MacからTXTをAirDropなどでiPhoneの「ファイル」に置き、「Apple Musicの書き出しTXTを取り込む」で選びます。「TXTの曲を選ぶ」から対象を選ぶと、名前とアーティストでApple Musicの候補を検索します。UTF-16/UTF-8のタブ区切りに対応しています。
- **曲検索**：曲名とアーティストを入力し、「候補を検索」を押します。

検索結果は自動で正解扱いにしません。アルバム名・曲長・ライブ版などを見て同じ録音版を選び、再生して確認します。TXTの対象曲を変更したい場合は曲一覧から選び直します。TXTには曲IDがないため、音源を確認して選ぶ工程が必要です。

## サビ位置の提出

1. シークバー、±1秒・±5秒、または「45秒付近へ移動」でサビを探します。
2. 「現在位置をサビにする」で、その瞬間のMusicKit再生時刻を記録して一時停止します。
3. ±0.1秒・±1秒で開始位置を調整します。
4. 「1.5秒前から確認再生」で頭が切れていないか聴き直し、「この録音版とサビ開始を聴いて確認した」をオンにします。
5. 「提出してXLSXを更新」を押します。同じ曲・ストアフロントの訂正は上書きし、別の曲やストアフロントは別レコードにします。
6. TXTを使っている場合は「次の未提出曲へ」で続けます。提出済みの曲も一覧の「未提出だけ表示」をオフにすれば訂正できます。

ミリ秒の数値を保存しますが、MusicKitが報告する再生時刻と人の操作に依存するため、音声サンプル単位の精度を保証するものではありません。最後の聴き直しで境界を合わせてください。保存する値は **サビの実時刻** です。確認再生の1.5秒前倒しは保存値から差し引きません。

## 保存される内容

アプリのDocuments配下の `ChorusDeveloper/` に保存します。

- `session-v1.json`：提出内容とTXTの対象一覧。再起動時に復元する元データです。
- `chorus-positions.xlsx`：全提出曲をまとめた最新のXLSX。提出のたびに更新します。

XLSXには名前、アーティスト、アルバム、サビ開始（分秒表示・秒・ミリ秒）、曲長MS、カタログID、ライブラリID、ストアフロント、ISRC、確認日時UTC、確認状態、取得方法、メモ、プレイリスト、TXTの元の行・名前・アーティスト、再生に使ったMusicKit IDを保存します。

ライブラリ曲のカタログIDはAppleの明示的な対応関係から取得します。取得できなかった場合もライブラリIDと聴いて選んだ録音の情報は保存しますが、**カタログIDが空の行は共通DBへ取り込む前に対応付けが必要**です。タイトルだけで別の録音版に時刻をコピーしないでください。

「最新のXLSXを共有・ファイルに保存」からAirDropやファイル保存を利用できます。端末に自動保存する処理と、端末外へファイルを渡す共有操作は別です。XcodeのDevices and Simulatorsからアプリのコンテナをダウンロードして、JSONとXLSXを取り出すこともできます。アプリを削除すると端末内の記録も削除されるため、作業の区切りで共有してください。

XLSXの更新に失敗しても、先に保存したJSONの提出内容は残ります。その場合は古いXLSXを最新として共有せず、エラーを表示します。「XLSXを再生成」で再試行できます。保存データの読み込みに失敗した場合は上書きを止めます。

今回はユーザー指定の選択肢のうち **XLSX自動生成** を実装しました。CloudKitへの書き込みや既存のゲームのサビ参照処理への接続は行いません。

## 検証

```sh
sh scripts/test_chorus_developer.sh
# ローカルにある実際のTXTも追加で検証する場合
sh scripts/test_chorus_developer.sh /path/to/IntoL.txt
```

保存・再提出・復元、冒頭0秒、範囲外時刻、TXTのUTF-16と引用符、XLSX失敗時の復元、独立したZIP/XML読み取り、文字列を数式にしない処理を検証します。Apple Musicの認証とフル楽曲の実再生は、契約のあるアカウントと実機で確認してください。

実装で使用するAPIの公式資料：[MusicKit](https://developer.apple.com/documentation/musickit)、[再生キューのcurrentEntry](https://developer.apple.com/documentation/musickit/musicplayer/queue/currententry)、[ストアフロントのcurrentCountryCode](https://developer.apple.com/documentation/musickit/musicdatarequest/currentcountrycode)。
