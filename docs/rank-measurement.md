# イントロランク測定

「ひとりで → ランク測定」から、Apple Musicの共通曲集で実力を測定する。プレイリスト選択は不要。アクセス許可・サブスクリプションが必要で、試聴音源への代替は行わない。

## 曲集と録音の照合

`server/rank-catalog.json` は歌ネットの歴代人気順1〜1000位から選び直した716曲・716課題の曲集。掲載発売日が2010年以降の545曲に、ユーザーがチェックした192曲を加え、童謡「きらきら星／カノン」を除いた736曲を選定した。このうち通常録音を照合できた716曲を出題し、未照合20曲は保留する。旧200曲の手動グループによる生成は廃止した。選定過程は `docs/rank-catalog-review.md`、保留曲は `docs/rank-catalog-pending.md` に記載する。

課題レベルは元順位1〜100位をLv1、以降100位ごとに1段階上げ、901〜1000位をLv10とする。課題レベルは曲の内部難度で、結果に表示するランクは下記の判定基準で求める。曲を除外しても元順位は詰めない。元の発売日は歌ネット掲載値であり、初出日とは限らない。録音情報はAppleの日本ストアの公開メタデータと既存のApple Music確認済み台帳から固定する。旧台帳のID候補は引き継がず、公開メタデータで確認できたカタログIDのみ候補に使う。

MusicKitのID候補を取得し、曲名・アーティスト・アルバムがすべて一致した場合のみ採用する。不一致の場合はカタログ検索の上位25曲から同じ条件で探す。Unicode NFKC・大文字小文字・空白の差は吸収するが、Live・Remix・Remaster等の文字列は削除しない。指定のアルバムを取得できない場合も別録音へ代替せず、課題を無効にする。結果のSongには実際のMusicKit IDも保存する。

歌ネットとAppleで副題・共演者・旧名・読み仮名等が異なる場合は、確認した表記の組み合わせのみ明示的に照合する。MusicKitとの録音照合にはApple側の正式メタデータを使い、回答・回答候補・結果には歌ネット側の曲名を使う。アーティストの上限は出典の歌手名を正規化したグループキーで数え、提供元の共演者表記で上限を回避させない。旧履歴に新しい回答名・グループキーがない場合は従来の曲名・歌手名を使う。

**初期のイントロは試聴・試遊による検証を終えたものではない。** レベル・制限秒数は編集上の仮値で、画面にベータ版と明示する。期限までに識別の手掛かりがあるかを実音源で点検し、旧曲の世代差も試遊で確認する必要がある。

```sh
python3 scripts/build_rank_catalog.py
sh scripts/test_rank_measurement.sh
```

チェックを反映する際は `python3 scripts/apply_rank_review.py`、メタデータを収集する際は `python3 scripts/collect_rank_metadata.py` を使う。ネットワークなしの再照合には `--cache-only` を付ける。公開APIは毎分19回以下で読み、音源や画像はダウンロードしない。保存済みのチェックは元順位・曲名・歌手名・曲ページを照合し、重複・欠落・不正なチェック値を拒否する。

## 推定と進行

- 最初の3つの有効な課題はLv1。Lv1には97の異なる録音を用意する。各レベルは旧曲を除いてもアーティスト上限の下で20問以上を確保できる。以降は推定正解確率が70%に最も近い課題を出す。事後分布全体で確率を平均し、同難度の候補はランダムに選ぶ。
- 録音を重複させず、直前の完了測定に含まれる録音も除外。同じアーティストは2曲、旧曲も2曲まで。再生できなかった課題も今回の候補から外す。上限は予約した課題に適用するため、通信不調時にも偏りを増やさない。
- 期限内にPUSHし、現在と同じ1文字4択・各文字5秒ですべて正解すると成功。文字数は回答前に表示しない。選択肢のコーパスには共通曲集を使う。
- 正答・誤答・スキップ・PUSH時間切れ・回答時間切れを区別する。PUSH時刻は音源の再生位置で測り、ロード待ちを含めない。期限後のPUSHを切り詰めて正解扱いにしない。
- 15問以降、隣接する2段階への事後確率が80%以上で終了。それ以外は20問で終了。無効課題は問題数・推定に加えない。
- アプリ非アクティブ、音声割り込み、再生位置の巻き戻り、2秒間再生が進まない場合は問題を無効にする。「別の曲で続ける」から再開できる。曲検索の失敗は最大8件ずつ置き換え、回復できない場合は理由と再試行を表示する。課題不足や途中終了にはランクを付けない。

### 固定した推定尺度

`rasch-v2` は `P(正解 | 能力θ, 課題難度b) = logistic(θ − b)`。能力の格子は−6〜6、間隔0.1。事前分布は平均0・標準偏差3の正規分布を格子上で正規化する。有効な成否だけで更新し、同じ課題の重複通知は無視する。

Lv1〜10の初期難度は−2.7〜2.7、間隔0.6。曲のレベルは累計歌詞アクセス順位による仮値で、PUSH期限は既存の初期値（Lv1から順に12・8・8・5・8・5・3・5・3・3秒）を使う。各ランクの境界は `b + log(0.7 / 0.3) − 2.4`。2026年10月14日に判定を4段階分ゆるめ、従来のDの能力帯がB+になるよう変更した。中央値を今回のランク、10%点〜90%点を測定幅にし、どちらにも新しい境界を適用する。保存レベル0〜10の表示名は順にF・E・D・C・C+・B・B+・A・A+・S・S+。最初の境界を満たさない推定は「F相当」、上限は「S+相当」。課題難度・PUSH期限・能力の推定方法は維持する。過去の`rasch-v1`の記録は再採点せず、最高記録は新しい推定器バージョンで別に保存する。測定幅は仮難度を前提にしたモデル上の幅で、実測による精度保証ではない。

校正には結果の `firstExposure` がtrueの有効回答を中心に使い、参加者の実力も考慮して難度を見直す。上級者への出題が多い曲の単純正答率を難度に変換しない。結果は個人のCloudKit Private Databaseに保存する。開発者へ回答を自動送信する仕組みは追加していない。

## 記録と互換性

CloudProfileの任意フィールド `rankRecords` に最近20回、曲集・推定器のバージョンごとの最高記録、過去に聴いた録音IDの台帳を保存する。端末のキャッシュとiCloud Private Databaseに同期する。通常のソロ履歴5回やF〜S+の計算・通常プレイ統計とは別に扱う。

プロフィールのバッジは履歴とバージョン別最高記録から、過去の曲集を含む最高レベルを求める。未測定は非表示、完了したFの測定はFを表示する。既存の称号と併存し、名前が長い場合や文字サイズが大きい場合は名前の下に折り返す。通常32ptの丸型で、最大ランクS+は二重の金枠を使う。

公開プロフィールの `PUT /profile` と `GET /player-profile` に任意の `highestRankLevel`（整数0〜10）を追加する。`GET /friends` と申請承認・拒否後の応答でも、各フレンドに同じ最高ランクを返す。フレンド一覧は一人ずつカードで表示し、名前の横にプロフィールと共通の丸型バッジを付ける。送信側は未測定なら項目を省略する。サーバーは認証済みプロフィールの最高値を保持し、低い値や旧クライアントからの省略で降格させない。不正値は更新前に400で拒否する。読み取りは未測定をnullで返し、旧サーバーで項目がなければアプリは非表示にする。履歴や個々の測定結果は公開しない。

ローカルのバッジは完了した結果の保存時に更新する。公開概要は既存プロフィール同期とルーム作成・コード参加・招待参加の前に更新する。公開に失敗してもプレイを継続し、次回同期で再試行する。サーバーを先に更新してからアプリを配布する。

## 検証

`sh scripts/test_rank_measurement.sh` で旧D→B+の判定・測定幅・旧基準との最高記録の分離・全正解・全誤答・境界・一度の誤答・期限境界・重複/前回曲/アーティスト/旧曲の除外・無効音源・枯渇・旧プロフィール・同期/最高記録の保持を確認する。

Debugの `--ui-preview=rank-setup`、`rank-listening`、`rank-error`、`rank-result` と、各 `-dark` / `-large-text` で音楽サービスに接続せず画面を確認できる。

実機試遊では、716曲の再生可否と冒頭の手掛かり、音源の開始遅延、ヘッドホンの遅延、音声割り込み、異なる曲による再測定、世代差、所要時間を確認する。目標は再測定の大部分が±1段階、通常のプレイが5〜8分。メタデータの照合・仮難度のシミュレーション・画面プレビューだけではこの目標を検証できない。
