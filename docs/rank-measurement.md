# イントロ段位測定

「ひとりで → 段位測定」から、Apple Musicの共通曲集で実力を測定する。プレイリスト選択は不要。アクセス許可・サブスクリプションが必要で、試聴音源への代替は行わない。

## 曲集と録音の照合

`server/rank-catalog.json` は200曲・203課題・各難度20課題以上・旧曲10曲の初期曲集。2015年以降の邦楽が中心。`scripts/build_rank_catalog.py` の編集グループから、既存600曲のサビDBにある曲名・アーティスト・アルバムを引き継ぐ。元DBの曲IDにはライブラリ由来の値もあるため、IDだけでは録音を確定しない。

MusicKitのID候補を取得し、曲名・アーティスト・アルバムがすべて一致した場合のみ採用する。不一致の場合はカタログ検索の上位25曲から同じ条件で探す。Unicode NFKC・大文字小文字・空白の差は吸収するが、Live・Remix・Remaster等の文字列は削除しない。指定のアルバムを取得できない場合も別録音へ代替せず、課題を無効にする。結果のSongには実際のMusicKit IDも保存する。

**初期のイントロは試聴・試遊による検証を終えたものではない。** レベル・制限秒数は編集上の仮値で、画面にベータ版と明示する。期限までに識別の手掛かりがあるかを実音源で点検し、旧曲の世代差も試遊で確認する必要がある。

```sh
python3 scripts/build_rank_catalog.py
sh scripts/test_rank_measurement.sh
```

元ワークブックが変わった場合、生成スクリプトは停止する。編集グループの参照先を点検してから更新する。

## 推定と進行

- 最初の3つの有効な課題はLv1。Lv1には23の異なる録音を用意し、前回20曲を除外しても3問を確保する。以降は推定正解確率が70%に最も近い課題を出す。事後分布全体で確率を平均し、同難度の候補はランダムに選ぶ。
- 録音を重複させず、直前の完了測定に含まれる録音も除外。同じアーティストは2曲、旧曲も2曲まで。再生できなかった課題も今回の候補から外す。上限は予約した課題に適用するため、通信不調時にも偏りを増やさない。
- 期限内にPUSHし、現在と同じ1文字4択・各文字5秒ですべて正解すると成功。文字数は回答前に表示しない。選択肢のコーパスには共通曲集を使う。
- 正答・誤答・スキップ・PUSH時間切れ・回答時間切れを区別する。PUSH時刻は音源の再生位置で測り、ロード待ちを含めない。期限後のPUSHを切り詰めて正解扱いにしない。
- 15問以降、隣接する2段階への事後確率が80%以上で終了。それ以外は20問で終了。無効課題は問題数・推定に加えない。
- アプリ非アクティブ、音声割り込み、再生位置の巻き戻り、2秒間再生が進まない場合は問題を無効にする。「別の曲で続ける」から再開できる。曲検索の失敗は最大8件ずつ置き換え、回復できない場合は理由と再試行を表示する。課題不足や途中終了には段位を付けない。

### 固定した推定尺度

`rasch-v1` は `P(正解 | 能力θ, 課題難度b) = logistic(θ − b)`。能力の格子は−6〜6、間隔0.1。事前分布は平均0・標準偏差3の正規分布を格子上で正規化する。有効な成否だけで更新し、同じ課題の重複通知は無視する。

Lv1〜10の初期難度は−2.7〜2.7、間隔0.6。各段位の境界は `b + log(0.7 / 0.3)`。中央値を今回の段位、10%点〜90%点を測定幅にする。5級を満たさない推定は「入門」、上限は「五段相当」。測定幅は仮難度を前提にしたモデル上の幅で、実測による精度保証ではない。

校正には結果の `firstExposure` がtrueの有効回答を中心に使い、参加者の実力も考慮して難度を見直す。上級者への出題が多い曲の単純正答率を難度に変換しない。結果は個人のCloudKit Private Databaseに保存する。開発者へ回答を自動送信する仕組みは追加していない。

## 記録と互換性

CloudProfileの任意フィールド `rankRecords` に最近20回、曲集・推定器のバージョンごとの最高記録、過去に聴いた録音IDの台帳を保存する。端末のキャッシュとiCloud Private Databaseに同期する。通常のソロ履歴5回やF〜S+の計算・通常プレイ統計とは別に扱う。

結果には課題、実際のMusicKit ID、成否、PUSH時刻、初回出題フラグ、無効理由、曲集・推定器のバージョンを残す。初回情報は古い結果が履歴から消えても保持する。未完了測定は履歴に加えないが、聴いた曲は初回台帳に残す。

端末間の履歴は測定UUIDで統合し、最高記録は履歴20回から消えても保持する。異なる曲集/推定器の最高記録は比較しない。旧プロフィールに `rankRecords` がなくても読み込める。難度を更新する際は曲集バージョンと `RankCatalog.bundledVersion` を更新する。自動の曲集更新や既存記録の再採点は行わない。

## 検証

`sh scripts/test_rank_measurement.sh` で全正解・全誤答・境界・一度の誤答・期限境界・重複/前回曲/アーティスト/旧曲の除外・無効音源・枯渇・旧プロフィール・同期/最高記録の保持を確認する。

Debugの `--ui-preview=rank-setup`、`rank-listening`、`rank-error`、`rank-result` と、各 `-dark` / `-large-text` で音楽サービスに接続せず画面を確認できる。

実機試遊では、200曲の照合と冒頭の手掛かり、音源の開始遅延、ヘッドホンの遅延、音声割り込み、異なる曲による再測定、世代差、所要時間を確認する。目標は再測定の大部分が±1段階、通常のプレイが5〜8分。仮難度のシミュレーションや画面プレビューだけではこの目標を検証できない。
